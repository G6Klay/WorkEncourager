# 上班鼓励器

右下角的置顶小窗：按排班自动切换上下班状态，每秒显示今天赚了多少，并计算还要工作多久才能实现小心愿。

## 运行

```bash
dist/WorkEncourager.exe
```

- 只有一个 exe，复制到哪里都能运行，不需要安装。发给别人时建议压缩成 zip。
- 运行环境是 Windows 自带的 .NET Framework 4.6.2 或更新版本（Win10 1607 起系统自带），以及 WebView2 Runtime（Win11 自带，大多数 Win10 已通过 Edge 更新装好，缺少时程序会弹窗提示）。
- exe 没有数字签名，Windows 可能提示“已保护你的电脑”，点“更多信息”再点“仍要运行”。
- 数据保存在 `%LOCALAPPDATA%\WorkEncourager\data.json`，不联网。旁边的 `data.json.bak` 是上一次保存的备份。同目录的 `runtime` 里是启动时释放的 WebView2Loader.dll，`WebView2` 是界面的缓存。
- 点小窗上的关闭按钮只是隐藏到托盘。要彻底退出，右键托盘图标选“退出”，或到“设置”里点“退出程序”。

## 规则

**日薪**：默认用月薪除以当月排班天数，所以每个月的日薪可能不同；也可以改成固定除以 21.75 天。已结算的日子不受之后修改的影响。

**午休**：不计薪。时薪和每秒金额都按扣掉午休后的工时计算，比如 09:00–18:00、午休 12:00–13:00，就是日薪 ÷ 8 小时。午休期间金额不动。每个班次在“参数设置”里单独设置午休；从旧版升级的存档默认没有午休，要手动打开。

**状态**：完全由时间和排班决定，不需要点“开始上班”。程序关闭或电脑休眠都不影响累计。

| 状态 | 什么时候 | 金额 |
| --- | --- | --- |
| 还没上班 | 今天有班，还没到点 | 显示距上班倒计时 |
| 工作中 | 工作时段内 | 日薪按秒累计 |
| 午休中 | 午休时段内 | 不变，显示距下午上班倒计时 |
| 该下班了 | 过了下班时间但还没点下班 | 按加班设置继续累计，到点提醒一次 |
| 已下班 | 点了“下班结算” | 固定为结算金额 |
| 休假中 | 今天全天节假日、调休、事假或病假 | 假期工资整笔计入，不需要点下班 |
| 休息中 | 今天没有班 | 显示距下次上班倒计时 |

**假期标记**：在排班页选好类型，点日历上的日期。再点一次取消。

- 节假日、调休、事假、病假只是标记，不改变排班，所以当月排班天数和日薪都不变：事假扣掉的就是这一天该得的钱。各自的工资比例在“参数设置”里手填，默认节假日和调休 100%、事假 0%、病假 60%。
- 调休、事假、病假可以选上午或下午。上午和下午按午休分开，没有午休时按班次中点分开。比如午休 12:00–13:00 时，上午假是 3 小时按比例、下午 5 小时正常上班；下午假则 12:00 就算到下班时间。
- 假期工资是整笔金额，请假时段一开始就计入，不按秒跳动。
- “休息”和假期标记不同：它把这天从排班里去掉，当月排班天数减一，日薪会变高。周末补班直接用班次点那一天。
- 已结算的日子事后再标记，金额和心愿会自动重算。没有排班的日子只做标记，不影响工资。
- 节假日上班没有单独倍率，按普通上班和加班设置计算。

**忘记点下班**：超过下班时间 8 小时（可在参数设置里改）或下一班开始时，自动结算。自动结算只算正常工资，不算加班费，否则睡一觉也会多出一笔加班费。可以在“记录”里改实际下班时间，或标记这天不计薪。

**一键核算**：“记录”页勾选“从 1 号起核算”后，本月金额从 1 号累计到现在：已结算的日子用结算金额，今天用实时金额，其余有排班的日子按排班和标记补算，比如开始用这个程序之前的日子。补算只用于显示，不写入记录，也不存入心愿。

**全屏让位**：小窗所在屏幕上有全屏程序（PPT 放映、全屏视频、游戏）时自动隐藏，结束后自动回来。这期间用托盘或再次打开 exe 手动调出后，这次全屏结束前不会再隐藏。下班提醒如果正好赶上全屏，窗口会等全屏结束再出现。不置顶时不需要让位。可以在“参数设置”里关闭。

**心愿**：收入按设定比例存入队列里排在最前面的心愿，蓄满后溢出给下一个，全部蓄满后进入未分配余额，添加新心愿时自动转入。今天还没结算的收入只做实时预览，结算时才入账。“还需工作多久”只按正常班次估算，不算加班。

**任务**：在“任务”页新建，可以立刻开始计时、加入清单，或者预约时间。同一时间只计一个任务，开始新任务会暂停正在计时的任务；计时按真实时间走，关掉程序也不会停；点“下班结算”时会自动暂停。结算后任务进入已完成记录，耗时和回报固定下来。

- 回报是这段时间对应的工资：上班时段按时薪，下班后按加班费，午休、休息日、全天请假和点了下班之后不计。所以总耗时可能大于计薪工时。回报已经包含在今日已赚里，不会重复计算，也不会另外存入心愿。
- 预约任务到点只提醒，不自动开始。填了结束时间的话，已经开始的任务会在结束前 5 分钟和结束时再各提醒一次，也不会自动结算。程序没开时错过超过 1 小时的提醒不再补发。
- 小窗卡片下方显示心愿进度还是任务进度，在“参数设置”里切换。任务进度模式可以开始、暂停和结算，也能直接新建并开始。迷你模式不显示任务。

**调整顺序**：如果排在最前面的心愿变了，而原来排第一的心愿已有进度，会询问进度留给它，还是转给新的第一名。把有进度的心愿往后挪、但第一名没变时，也会询问是否把进度交给接替它位置的心愿。把心愿往前挪、又没有改变第一名时不询问。

**按月排班**：还没排班的月份，估算心愿时沿用最近一个已排班月份的日期，并在界面上注明是估算。

## 项目结构

```
web/core.js     排班、计薪、心愿的全部逻辑，不依赖界面，以后做手机版可以直接复用
web/app.js      界面
web/styles.css  样式，跟随系统的浅色和深色主题
src/            C# 外壳：窗口、托盘、通知、读写文件、开机自启、全屏检测
tests/          核心逻辑测试
scripts/        运行测试、生成图标的脚本
```

`web/` 里的文件和 WebView2 的依赖编译时都会嵌入 exe（见 `src/EmbeddedDependencies.cs`），修改后要重新构建才生效。

## 开发

运行测试（用系统自带的 Edge，不需要 Node）：

```bash
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run-tests.ps1
```

构建并把 exe 复制到 `dist/`（需要 .NET SDK，运行时不需要）。`dist/` 里的 exe 正在运行时复制会失败，要先退出程序：

```bash
dotnet build WorkEncourager.csproj -c Release
```

外壳的目标框架是 .NET Framework 4.6.2，所以 C# 代码不能用新版 .NET 才有的 API，比如 `System.Text.Json`、`Math.Clamp`。

测试时把环境变量 `WORK_ENCOURAGER_DATA_DIR` 指向一个临时目录，就不会碰到正式数据，也能和正式程序同时运行。

## 安全设计

这个程序是用来替代一个有注入风险的 HTA 的，所以有几条约束，改代码时请保持：

- 界面不使用 `innerHTML`，存档里的内容只会被当成文字显示。
- 读档时由 `normalizeState` 校验所有字段，丢弃结构或类型不对的内容。
- 页面启用了严格的内容安全策略（CSP），不允许内联脚本，也不访问任何外部地址。外壳禁止跳转到外部网页、打开新窗口、下载和申请权限。
- 外壳只响应固定的几种消息，文件路径都写死，页面无法指定读写哪个文件。
